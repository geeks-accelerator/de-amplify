# CLAUDE.md

Operational guide for working in this repo. For what the project *is* (the thesis, the document structure, the routes), read [README.md](README.md). This file is the conventions and gotchas that keep it from breaking.

## Standalone repo (hard rule)

This repository is self-contained and public. Do **not** add references to any other, sibling, or private repository: not by relative path (e.g. `../other-repo/...`), not by project name, and not in commit messages. If you need a concept that lives in another project, describe it inline here instead of linking to or naming the source. The git history was scrubbed of such references before this repo went public; keep it that way.

## House style (load-bearing)

- **No em-dashes.** The house style forbids the em-dash and the en-dash used as punctuation. Use commas, colons, parentheses, or restructure the sentence. This applies to content, code comments, and commit messages alike. Curly/smart quotes are also out; use straight quotes. In a TS/TSX string that needs a straight double quote, escape it (`"\"Show me less\""`) rather than reaching for a curly pair.
- **Checking it (the naive grep lies on macOS).** `grep -l $'[‘’“”]'` over-reports badly here: BSD bracket collation matches U+2014 and other punctuation, so it flags files with zero curly quotes and sends you chasing ghosts. Use one exact codepoint per pattern under the C locale:

  ```bash
  LC_ALL=C grep -rn --exclude-dir=sources --exclude-dir=reviews \
    -e $'—' -e $'‘' -e $'’' -e $'“' -e $'”' src/ content/ docs/ *.md
  ```

  Sweep `docs/` and the root `.md` files too, not just `src/` and `content/`: the last em-dash found in this repo was in `docs/plans/`, which a `src content` only scan never reaches. The two `--exclude-dir`s are the exemptions below. This file will always self-match (it contains the literal characters in the line above); that is the one expected hit.

  **Directories named `sources` or `reviews` are deliberately exempt**, because their punctuation is evidence rather than prose: `docs/distillations/sources/` (verbatim official transcripts, whose GPO punctuation the ledgers reproduce exactly), `docs/distillations/reviews/` (raw output from external review models, referenced as `raw_audit_trail` in ledger frontmatter), and `docs/reviews/` (whole-repo external audits, filed verbatim). Rewriting punctuation in any of them is editing a record of what someone else said. Everything else, including `src/`, `content/`, `docs/proposals/`, `docs/plans/`, and this file, is held to the rule.

  **Note the mechanism, because it is easy to break by tidying.** `--exclude-dir` matches a directory's *basename at any depth*, which is why `docs/reviews/` inherited an exemption written for `docs/distillations/reviews/` without anyone adding it. That is convenient and slightly accidental: if the sweep is ever tightened to match full paths, every exempt directory has to be listed explicitly or CI goes red on the first quoted em-dash. Verified 2026-08-14 with a positive control (the filed audit really does contain 4 em-dashes and 3 curly apostrophes; the sweep passes anyway).
- **Commit messages**: lowercase, colon-prefixed by area (`site:`, `content:`, `docs:`, `scorecard:`, `proposal:`), imperative mood, body wrapped. End with the `Co-Authored-By:` trailer when co-authored. Commit and push only when asked.
- **`main` is protected: it takes pull requests, not direct pushes.** A direct `git push origin main` is rejected with `GH006: Protected branch update failed`, and the rule applies to admins too. Work on a branch, open a PR, merge it (0 approvals required, no required status checks, so a solo maintainer is not blocked, just routed). The `(#25)` / `(#27)` suffixes on subject lines in `git log` are squash-merge artifacts, not something to type by hand. Merging is what deploys: Railway builds `main`.
- **Voice**: the copy is confessional, direct, terminal/mono in feel (Geist Mono, the void / brake-red palette). Match the surrounding text; do not turn it into marketing.
- **Contrast floor: real text clears WCAG AA 4.5:1 against the void.** The muted palette is the look, but the bottom of the opacity ladder was illegible (`text-bone/30` measured 2.28:1), so on 2026-07-24 it was remapped repo-wide: `bone/20 -> 52`, `30 -> 55`, `35 -> 57`, `40 -> 60`, `45 -> 63`, plus `brake/70 -> 90` and `signal/60 -> 80` on real text. **`text-bone/50` (4.51:1) is the floor; do not go below it for anything a reader reads.** All the site's type is under 24px, so the large-text 3:1 allowance never applies. Genuinely decorative glyphs (the footer `/` separators, the terminal `>` prompt) keep their low opacity and carry `aria-hidden="true"` instead; the one other exemption is the `prose-li:marker:` bullet, which is `::marker` decoration on a semantically-marked list. Adding `text-bone/40` for new copy silently reopens the whole class. **Keyboard focus is part of this floor and lives in one place, `src/lib/focus.ts` (`FOCUS_RING`).** It was briefly copy-pasted into four components, which is how a repo-wide rule stops being repo-wide: someone adjusts one copy and the other three keep the old value while still looking deliberate. Use `:focus-visible`, never `:focus`, so a mouse click does not paint a ring nobody asked for; brake at full opacity measures 6.21:1 against the void.

## Content pipelines (know which one you are in)

- **Policy paper and appendix.** `content/proposal.md` and `content/notes.md` are the frontmatter-stripped *bodies* of the review copies in `docs/proposals/`. Edit the review copy, then regenerate the body. Do not add nav links or frontmatter to `content/*.md` (react-markdown renders them raw).
- **`docs/proposals/` is not one thing, and the difference is dangerous.** It holds four kinds of file that look identical: two **live review copies** (the two above), three **live deck sources** for `/for` (read directly by `llms-full.txt`), one **open proposal** (scorecard v2), and at least one **superseded artifact**: `2026-07-15-the-social-media-addiction-lawsuits-explained.md` was the original review copy of `/lawsuits` from before that page moved to the ledger-first pipeline. It has not been maintained since, and as of 2026-07-25 it differs from the live page in about fourteen passages where the live page is the correct one. **Regenerating `content/lawsuits.md` from it would silently revert months of ledger-first corrections.** Its frontmatter now says so; check for a `superseded:` key before treating anything in that folder as a source.
- **Lawsuits and hearings are ledger-first.** `docs/distillations/*.md` are the evidence-tiered claim ledgers and are the source of truth. `content/lawsuits/*.md` (the case files), `content/lawsuits.md` (the hub), and `content/hearings.md` (the hearings hub) are *seeded from* the ledgers, curated, not a 1:1 render. Corrections land in the ledger first (verified against a primary source), then the page is re-seeded on a dated pass. Never fix a fact only on the page.
- **The ledgers are also published directly.** `/distillations/<slug>` (plus a raw `/distillations/<slug>.md` per ledger, and inclusion in `/llms-full.txt`) renders each ledger via the section whitelist in `src/lib/distillations.ts`: reader summary, brake-integrity relevance, the tiered claims, the full quote-bank, tensions, plus Sources rebuilt from frontmatter and the lawsuit ledgers' own Tier key paragraph. The TLDR block, Discrepancies, and Coverage note stay out (authoring/QA scaffolding). So a ledger correction publishes to `/distillations` automatically with no re-seed; only the curated pages need the dated pass. A new ledger needs **both** an entry in the `DISTILLATIONS` list in that lib file **and** a filled-in TLDR block (see the two bullets below); registering it without the TLDR variants yields a blank index card and an OG card that falls through to the generic "The evidence ledger" title.
- **Verbatim TLDR surfaces.** Each ledger has a TLDR block of budgeted variants (label / nav-label / og-title / search-snippet / ledger-snippet / one-sentence / one-paragraph). Those exact strings are wired verbatim into consumers, **one consumer each**: label -> hub card (`content/lawsuits.md`, the `content/hearings.md` table), nav-label -> the `/distillations` index card and breadcrumb, og-title -> the share card, search-snippet -> the **curated page's** meta description, ledger-snippet -> the **`/distillations/<slug>` page's** meta description, one-sentence -> JSON-LD description, one-paragraph -> page opener. The one-consumer rule is load-bearing for SEO, not just for drift: search-snippet briefly had two consumers (the case page copied it verbatim while the ledger page parsed it), which shipped **identical meta descriptions on two indexable URLs about the same case**. Ledger-snippet exists to break that tie and is optional, because the hearing ledgers share one `/hearings` page and so have no collision to break. Everything except the hub card is parsed at build by `src/lib/distillations.ts`. Copy verbatim; do not hand-adapt a summary (an adapted copy is a third unvalidated variant and reopens drift). If a consumer needs a length the ledger lacks, add that budgeted variant to the ledger, not to the page.
- **`DISTILLATIONS` in `src/lib/distillations.ts` holds routing config only** (slug, kind, tierDown, related). Do not put a reader-facing string there. Nav-label and og-title used to be hand-authored in that array, which made them unvalidated variants of summaries the ledgers already owned; they are now parsed from the ledger like every other variant. A new ledger needs its TLDR block filled in, not new strings in the array.
- **The two action pages share their data with their raw markdown, and must keep doing so.** `/scorecard` and `/report` are hand-built React with no `content/` body, but they also have raw `.md` twins (`/scorecard.md`, `/report.md`) and appear in `llms-full.txt`. **The criteria and the form vocabulary live once, in `src/lib/actionPages.ts`**, and the page, the raw route and the bundle all render from those arrays. Do not hand-write a markdown copy of either page: the scorecard's seven criteria are already held in lockstep with section 3 of the policy paper, and a third hand-maintained copy is precisely the drift this repo builds checkers to prevent. Changing a criterion in that lib changes all three surfaces together; it does **not** change the paper, which stays a deliberate human edit. Note that `ReportForm.tsx` is a client component and imports from this lib, so keep the module free of anything heavy: verified 2026-08-14 that tree-shaking drops the scorecard half and the markdown generators from the client bundle (probe on string literals, not on symbol names, which minifiers rename).
- **Hand-built React** (not markdown): the homepage, `/report`, `/scorecard`, `/for`, `/remixes`, and `/distillations` (which renders the ledgers).
- **The table of contents is server-rendered, and its anchors must agree with `rehype-slug` or they silently do nothing.** `src/components/Toc.tsx` renders a collapsed contents list on `/proposal`, `/notes`, `/lawsuits` and `/hearings` from the same markdown string the renderer already receives, so it ships no client JS (a TOC that needed a hook would reship the parser the rule below exists to keep out). `src/lib/toc.ts` reimplements github-slugger's algorithm, **including its `-1`/`-2` duplicate suffixes**, because that is what `rehype-slug` uses to build the heading ids. If the two ever disagree, every link becomes a no-op: the page still renders, the anchor still looks fine, and nothing scrolls, which no build can catch. Verified against the ids actually in the DOM (13 of 13 on `/lawsuits`, 15 of 15 on `/proposal`) and unit-tested for the duplicate path, which no current document exercises. It also skips fenced code blocks, so a `## ` inside a shell example is not mistaken for a heading.
- **The markdown renderer is a server component, deliberately.** `src/app/proposal/ProposalContent.tsx` renders every markdown document (`/proposal`, `/notes`, `/lawsuits`, the case files, `/hearings`, the ledger pages). It has no `"use client"` and must not get one: react-markdown 10's default export has no hooks, so it renders server-side fine, and adding the directive reships react-markdown + remark-gfm + micromark + rehype-slug (measured: **42 KB gzipped**) to every document route *and* serializes the whole markdown string into the flight payload on top of the HTML it already rendered. There are **three** client components: `src/app/report/ReportForm.tsx`, `src/components/SunoEmbed.tsx`, and, since 2026-08-14, `src/components/HeaderNav.tsx`. **The rule is about shipping a parser, not about banning interactivity**, so read it that way before adding a fourth. `HeaderNav` exists to put `aria-current="page"` on the active link, which needs `usePathname`; it imports no library, and `next/link` already puts the App Router context in the client bundle on every page, so the measured cost was **301 bytes gzipped** (177,796 -> 178,097 total client chunks, built both ways from a cold `.next`). That is 0.6% of the 45.8 KB the rule exists to keep out. A candidate fourth that pulls in a dependency is a different question from one that does not; measure it the same way rather than arguing from the rule's wording.

## Evidence discipline (this is a public legal site)

- A legal or factual claim must trace to a **primary source** (a court order or filing, the docket, an official government release) to be stated as fact. Secondary coverage gets tiered down and flagged.
- **Posture precision.** "Announced intent" is not "filed" is not "affirmed"; a summary-judgment ruling is not a motion to dismiss; a jury verdict is not "upheld on appeal." The project was burned once by a "$6M upheld on appeal" error; do not repeat that class.
- **Event date is not coverage date.** An order "filed June 29" may be "announced June 30"; record the event date, note the coverage date. This error recurred repeatedly, so watch for it.
- Everything carries an **as-of date**. Figures date quickly.
- **A search that returns nothing is a claim about your query, not a fact about the record.** Prove the query with a positive control before reporting an absence: run it against a string you already know is in the source, and if the control comes back empty the query is broken, not the corpus. On 2026-07-25 a case-sensitive grep for prepared-statement markers returned zero against a record containing seven, and the zero was believed because it agreed with the expected answer. A hit is self-evidencing; a miss evidences only that you trusted the search. Bias ad-hoc checks toward over-matching: a false alarm gets investigated, a false all-clear gets published.
- **Some court hosts answer a bot-scented request with 404 rather than 403, which turns a refusal into a false absence.** Established 2026-08-28 on the JPML, whose pending-actions reports are cited throughout the MDL ledger. `curl -A "Mozilla/5.0"` returns **404** for a file that exists; a full browser user-agent string, or no user-agent at all, returns **200**. Isolated with a three-trial matrix holding one variable at a time, after two earlier explanations (that the Panel rotates old reports off the site, that the host requires a `Referer` header) were both wrong and both diagnosed from the same broken query they were meant to explain. **A 403 tells you that you were refused; a 404 tells you the thing does not exist, and only one of those is a claim you would go on to publish.** Two rules follow. Send a full user-agent when probing court infrastructure. And **do not guess a filename from a pattern**: JPML dates its files by publication day, so `June-1` and `July-1` are followed by `August-3`, and a guessed `August-1` 404s in a way indistinguishable from "not published yet". Read the index (`https://www.jpml.uscourts.gov/pending-mdls-0`) and take the filename from it. The whole sequence, including the two wrong diagnoses, is in `docs/plans/2026-08-28-settlement-and-audit-passes.md` section 3.1.
- **An official channel is not automatically the fullest record, and "best source" is not the same as "most complete".** Established 2026-08-20 on the attorneys general press conference of 2026-08-18. The California Department of Justice, whose office held it, published 23:26 on its own channel: the recording ends on the words inviting questions and **omits the entire Q&A**. PBS NewsHour published 52:20 of the same event including all of it, and the exchange that answered a live Tension in the MDL ledger falls in the 29 minutes the official version does not contain. Three separate passes retried the official URL over two days without once asking whether another recording of the same event existed, because official outranks secondary in this project's tiering and that ranking was silently read as completeness. **They are different properties.** For any public event on video, enumerate the recordings and compare durations before choosing which to keep; it is one search and it costs nothing. Related: **a caption track listed by `yt-dlp` under "subtitles" rather than "automatic captions" tells you the track was uploaded, not that a human wrote it.** The uploaded track for that event was machine output, and less accurate than hosted ASR on the same audio. There is no cheap flag for provenance here; read a passage you can check.
- **The quote-fidelity check is sensitive to five normalizations, and applying some but not all moves the error rather than removing it.** A full re-run over the four hearing ledgers verifies **245 of 246** spans, but only with all of them: fold curly punctuation (the testimony PDFs use curly apostrophes, the ledgers straight), split on ellipses (an elided quote is fragments, not one string), rejoin GPO's hyphenated line wraps (`core well- being` in the cache is `well-being` in the ledger), fold typographic ligatures (scanned court filings carry `ﬁ` as one character, so `sufﬁcient` never matches `sufficient`), and strip the **line numbers US court filings carry in the left margin of every line**, which `pdftotext` keeps and whitespace-collapsing then injects mid-sentence (`devices other than 11 computers and smartphones`). Miss one and you get failures that read exactly like fidelity defects, and the ligature case is the worst because the two strings look identical on screen. Details and the single known real deviation are in `docs/distillations/sources/README.md`. **The fifth of those normalizations had its bound corrected on 2026-08-28** (a widening, not a sixth normalization; "sixth" already names the `Lbl` tagged-PDF artifact below): the line-number rule allowed at most eight leading spaces, which is right for a GPO transcript and a party filing but wrong for an order on the Northern District of California's own template, where a rotated marginal caption is laid out *ahead of* the line number and pushes it past column 30. Every multi-line sentence in the trial order and the consent judgment failed as if fabricated. The bound is now unbounded leading whitespace, with self-test controls in both directions (a court order on that template must normalize; a numbered list item must keep its number), verified against every span then in the corpus (the count lives in one place, the coverage line of `docs/distillations/sources/README.md`, and `npm run check:quotes` asserts it). **This is now executable: `npm run check:quotes`.** Do not re-derive it by hand or with an ad-hoc grep; the script applies all five normalizations together, which is the whole point.
- **Verbatim is not the same as attributed, and only the first is machine-checked.** The quote-fidelity checker confirms a quoted span is an exact substring of the cached transcript. It cannot tell you *who said it*. A 2026-07-24 re-seed put a witness's line in a senator's mouth on `/hearings` and passed every check, because the string really was in the transcript. In the hearing ledgers' witness quote-banks the senator named in each parenthetical is the **questioner**, never the speaker; the speaker is the subsection. When re-seeding a quote, confirm the speaker against the transcript by eye, not by substring.
- **An English rendering of a non-English source is a translation, not a quotation, and must never appear inside quotation marks attributed to the court.** The two Dutch judgments in `bits-of-freedom-v-meta` are the corpus's first non-English sources and they set the convention for every future one: **the quoted span in the ledger is the original-language text**, so `npm run check:quotes` can verify it against the cache, with the English beside it explicitly labelled as a translation. On reader-facing pages, paraphrase in the site's own voice and cite the paragraph number rather than quoting Dutch at a reader who cannot read it. This is not pedantry about attribution, it is what makes the check mean anything: had that ledger quoted the English, every span in it would have had to be allowlisted and the checker would have proved nothing about its fidelity to the court.
- **Punctuation that is not in the source goes outside the closing quote.** `"...the absence of Meta's competitors in this litigation".` not `"...in this litigation."` The verified ledgers already do this; the FTC ledger's Claims section did not, and that is exactly how four spans drifted while looking perfectly ordinary. A period inside the quote is a claim that the source's sentence ended there.

## Adding or changing a route

Wire it into every discovery surface or it drifts out of sync:

- `src/app/sitemap.ts`, `src/app/llms.txt/route.ts`, `src/app/llms-full.txt/route.ts`, and the `_links` (plus a `skill` where it fits) in `src/app/agent-card.json/route.ts`. `_actions` in the agent card is capped at five, so extend `_links`, not `_actions`. A rendered document also gets a raw-markdown route (e.g. `/hearings.md`, `/distillations/<slug>.md`) with RFC 8288 `Link` headers (`up` / `index` / `canonical`), and is listed in llms.txt. **Since 2026-08-14 that includes the two ACTION pages**: `/scorecard.md` and `/report.md`, which are not read off disk but GENERATED from `src/lib/actionPages.ts`, the same arrays the pages render. They exist because the agent card's `_actions` send agents to run the scorecard and file a report, and the bundle those agents are told to read used to contain neither. Raw `.md` routes are deliberately **not** in the sitemap: they carry `rel="canonical"` back to the styled page, so indexing authority consolidates there rather than splitting across two URLs for one document. Note that `llms-full.txt` reads from **two** trees: the `content/` bodies plus, for the three `/for` briefing decks, their source files in `docs/proposals/` (the decks are gamma.app source with no `content/` body, but they are rendered documents, so "every rendered document" has to include them). The agent card's per-ledger `_links.ledgers` is generated from the `DISTILLATIONS` registry rather than hand-listed, so a new ledger wires itself in; the `/for` and `cases` branches are still hand-listed. **`llms.txt` follows the llmstxt.org format, verified against the spec on 2026-08-14**: every resource is its own markdown list item (a hyperlink, optionally `:` and notes), never several comma-separated links in one bullet, and the trailing `## Optional` section is the spec's own convention for resources an agent can skip when its context budget is tight. The rendered-HTML twins, the song page and the repository live there; the substance does not. The `## Pages` and `## Source` sections no longer exist. **As of 2026-08-13 the `llms.txt` ledger list is generated too**, grouped by `kind`, labelled with each ledger's own `navLabel` and counted from the registry: it used to be nine hand-written labels plus the literal word "Nine", which is three unvalidated variants per ledger and a count that goes stale silently. The agent card's `as_of` is likewise **derived** (the newest ledger `as_of`) rather than the literal it was, which had already gone stale by a week.
- If it is a content page: add `Article` + `BreadcrumbList` JSON-LD and **per-page `openGraph` / `twitter`** metadata. The OG image is a **colocated `opengraph-image.tsx`** in the route folder (it calls the shared `ogCard` in `src/lib/og/template.tsx`, brake or signal accent); Next wires it into `og:image` automatically, so the per-page `openGraph` object does **not** set `images`. A dynamic route generates one OG per param via `generateStaticParams` (see `/distillations/[slug]`). Do not build class names dynamically (`text-${accent}`); Tailwind cannot see them, so use literal ternaries.
- Dates in JSON-LD and the sitemap come from **`content-dates.json`**, a committed manifest of git author dates, via `src/lib/contentDate.ts`. Not `fs.statSync().mtime` (a fresh checkout resets mtimes to deploy time, restamping every page on every deploy) and **no longer a live `git log` at build time** either, because that silently failed on Railway for weeks. **If you change content, run `npm run dates` and commit the manifest with it**; `npm run check:dates` fails the pre-PR check if you forget. Do not reintroduce mtime, and do not reintroduce a build-time shell-out to git as the primary source.

There is an open revision proposal, `docs/proposals/2026-07-16-scorecard-v2-brake-performance-test.md`; the current seven-part test stays operative until that clears review, so do not quietly edit the dimensions out of band.

## Dependencies and runtime (one source each)

The stack runs current majors (Next 16, React 19, Tailwind 4, ESLint 10, TypeScript 6) on **Node 26**. Since 2026-10-24 every version this repo depends on is declared in exactly one place, and that is the rule to keep:

- **Node: `engines.node` in `package.json`, nowhere else.** Every CI job reads it (`actions/setup-node` with `node-version-file: package.json`) and Railpack reads it for the production build. **It is an exact version (`26.12.1`), and it must stay exact.** Railpack does not honor a range's floor: its `resolveToFuzzyVersion` cuts `^26.12.1` (or `>=26.12.1`) down to the bare major `26` and asks mise for the latest 26.x it knows, which on 2026-10-24 was 26.11.1, the release *before* the security fix this pin exists for. The first deploy of this setup shipped exactly that, and `/api/health` caught it within four minutes. Only an exact version passes through unchanged. So **every Node security release is a one-line edit here** (plus the matching root `engines` line in `package-lock.json`), `npm run check:node` is what tells you one shipped (it fails on PRs and in the weekly run until the pin catches up), and `/api/health`'s `runtime.matchesEngines` is how you confirm production took it. The health payload reports the major line and that boolean, deliberately not the exact version: publishing the patch level advertises which runtime CVEs apply on exactly the day production is behind. The 26 line is LTS from 2026-10-28 and supported to 2029-04-30. Before 2026-10-24 the version lived in five places that disagreed (`nixpacks.toml` 20, `engines` `>=20`, CI 20/22/20, `@types/node` 26), and production ran Node 20 for six months past its end of life.
- **Packages: `package-lock.json` is the production pin.** CI's `npm ci` fails when `package.json` and the lockfile disagree, so on any green commit they are in sync, and Railpack's install then resolves exactly the committed tree. The lockfile records the Linux native binaries (gnu and musl) for `@next/swc`, `@tailwindcss/oxide`, `lightningcss`, `@img/sharp` and `@unrs/resolver-binding`, so it installs on Linux from a macOS-generated file. **Regenerate it from an empty `node_modules`** (`rm -rf node_modules package-lock.json && npm install`): with the old tree present, npm keeps any installed version that still satisfies its range, which on 2026-10-24 silently kept `zod` inside an advisory range. Then `npm ci` before trusting a build, or you verify a tree the repo no longer declares. (Until 2026-10-24 the Railway build deleted the lockfile before installing, which made production unreproducible and the exact versions in `package.json` its only real pins. That is gone.)
- **The repo is ESM** (`"type": "module"`). Every config is ESM (`next.config.mjs`, `eslint.config.mjs`, `postcss.config.mjs`), and scripts run as plain `node`: Node 26 strips TypeScript natively, so `check:ledgers` imports `src/lib/distillations.ts` with no flags.

Deliberate pins and their exit conditions:

- **`next` and `eslint-config-next` are pinned exactly and move together.** 16.4.3 since 2026-10-24, which cleared a critical advisory set including an RCE in `next/og` `ImageResponse` (the API every OG card here uses). Track `next`'s advisories yourself; `sharp` rides in as its optional dependency.
- **`typescript-eslint` and its eight siblings are pinned via `overrides`, at 8.72.0.** They hold TypeScript below 6.1: 8.72.0's peer is `typescript: ">=4.8.4 <6.1.0"`. **TypeScript 7 is stable (7.0.2) and stays out until a `typescript-eslint` release widens that peer.** That is the one upgrade this repo is waiting on, and it waits on a third party.
- **`postcss-selector-parser` is overridden to 7.1.7** because `@tailwindcss/typography` pins 6.0.10 exactly, inside an advisory range. Compiled `prose` CSS is identical either way. Drop the override when typography ships a release whose range admits >= 7.1.6.
- **`tailwindcss` and `@tailwindcss/postcss` are pinned exactly together** (4.3.3); bump them as a pair.

**ESLint 10, for the record.** It was blocked from 2026-08-14 to 2026-10-24 by `TypeError: scopeManager.addGlobals is not a function`. The cause was `eslint-config-next`, which applies its own Babel-backed parser to every file, not `typescript-eslint` (an earlier version of this entry blamed the wrong package, and that sent an investigation the wrong way). `eslint-config-next` 16.4.x fixed it, as predicted, with a Next release. Dependabot #45 was merged red and reverted during that window: **re-test any lint major with `npm ci && npm run lint` and never trust a peer range.**

Dependabot keeps proposing majors and its exact version numbers are sometimes phantom (they 404). - **CI runs all of these, and it did not used to.** `.github/workflows/ci.yml` runs lint, build, **every `check:*` script** and the house-style sweep on every PR. It said "the three checks" until 2026-08-20, by which point there were six; the count is deliberately not restated here now, because `npm run check:guards` asserts that the list in the block above matches `package.json` and the workflow. Every job runs the Node version from `engines`, the same one production runs. `fetch-depth: 0` is on the guards job only, because `check:dates` compares against real git author dates and a shallow clone would report drift on every path. A third, non-gating `staleness` job runs `npm audit --audit-level=high` and `check:node`: an advisory or a Node security release is worth seeing on every PR but should not block an unrelated content fix. **That job, and only that job, also runs weekly on a schedule**, because both checks can go red without a commit, and a check that only ran on push let `main` sit green from 2026-08-29 through a month of critical Next.js advisories. The concurrency group includes the event, so the weekly run and a push to `main` cannot cancel each other. Until 2026-08-13 every guard in this repo was a command a human had to remember, which is a strange gap in a project whose whole discipline is catching drift that looks exactly like correctness.

- **`npm run check:ledgers` guards the one-consumer rule where a human does the copying.** Most TLDR variants are parsed from the ledger at build, so they cannot drift; four are hand-copied and those are exactly the ones that have drifted. It asserts, for all eleven ledgers: `One line (label)` appears verbatim in its hub (`content/lawsuits.md` or `content/hearings.md`), `One paragraph` in the curated case page's opener, `Search snippet` in the route file's `DESCRIPTION`, `One sentence` in that file's JSON-LD `description`, and, in the negative direction, that `Search snippet` does **not** also appear in the page body and `Ledger snippet` does **not** appear in the case route file (that pair is the two-indexable-URLs-same-description bug). It imports the real `loadDistillation` rather than reimplementing the TLDR parser, so the checker cannot disagree with the build. Exit 1 with the offending ledger, variant, consumer, and the ledger's own string on failure. **The fix direction is always ledger first, then re-seed the consumer**; the failure message says so, because editing the ledger to match a stale page is the tempting wrong move.
- **Two proven catches, and one it found on its first run.** Fault-injected and confirmed to fail on: the exact 2026-07-25 K.G.M. defect (page re-seeded everywhere except its opener), a one-hyphen hand-adaptation of a route `DESCRIPTION`, and the search snippet copied into a page body. On its first real run it caught a live orphan: the EU ledger's `One line (label)` had no consumer at all, because the hub carried a hand-written sentence instead of the label. **A variant with no consumer is a silent unvalidated string**, which is the same failure wearing different clothes, so the hub now carries it verbatim.
- **`check:ledgers` also asserts every registered ledger has a raw `.md` route, added 2026-08-13.** This closes the one surface a new ledger did **not** wire itself into. The agent card's `_links.ledgers` is generated from `DISTILLATIONS` and emits a `markdown:` URL for every ledger, but `/distillations/<slug>.md` is a hand-created route folder per slug, so registering a tenth ledger would have published a machine-readable link to a 404 while the page, the OG card, the sitemap and `llms-full.txt` all self-wired. A ledger can be registered whole, with an allowlist for deliberate drafter prose (the Nov 2023 and EU ledgers), or scoped with `sections` to just the part a cache covers (New Mexico, whose pre-judgment history quotes uncached coverage, plus Bits of Freedom and the FTC ledger). **Scoping is the check's own blind spot and it has already hidden real defects.** The FTC and Bits of Freedom ledgers were first scoped to `Quotes`, on the reasoning that the quote-banks hold the record quotes; the **Claims** sections quote the same caches, and being unchecked had absorbed sentence punctuation *inside* four quotation marks (the Eighth Circuit's `procedural error.` written as `procedural error,`, the Chitika order's `their choice(s), and shall remain` written as `their choice(s).`). Widening both to `["Claims (the ledger)", "Quotes"]` on 2026-08-14 raised coverage by roughly thirty checked quotations and surfaced all four at once. **Scope to what the cache covers, not to where you expect the quotes to be**, and re-read the exclusion whenever a ledger grows. **That rule has now failed three times in this one ledger, and the third time is the argument for changing the habit rather than the wording.** On 2026-08-28 `mdl-3047` section **(h)** was found to have been quoting four MDL orders since 2026-07-25 with none of them cached and the section outside the scope, so six real quotations of real court documents were unverifiable and nothing was red. Widening the scope to (h) and caching the four orders immediately surfaced **two genuine defects** in those six spans: CMO 36's calendar caption is a *stacked block* that the ledger had quoted as a slash-joined single line (a reconstruction, not a quotation), and a span had its source em-dashes silently swapped for a comma to fit the house style, inside the quotation marks. **The operational fix is a habit, not a rule: when you add a cache, grep the whole ledger for every section that quotes that document, and scope to what you find, not to the section you had in mind.** The earlier statement of this lesson follows.

**That rule then failed again on 2026-08-18, in the pass that was writing it down**: `mdl-3047` was registered with four caches and scoped to section (i), where the new trial-day quotes were, while section (e) had meanwhile acquired three claims quoting Dkt 473 from that same cache list, carrying the pass's most consequential correction. An audit found it; the check could not, because it cannot see what it is scoped away from. **The scope gets written when the cache is added and is never re-read when the ledger grows, and that is now a twice-proven failure rather than a caution.** Three things about it are deliberate: it **self-tests its matcher against known answers and aborts** rather than reporting a clean corpus it cannot actually read (a broken matcher reports green, which is this repo's recurring failure); a **declared-but-missing source or allowlist is a loud failure**, because the first draft of the script silently fell back to an empty allowlist and invented five phantom failures; and it **prints per-ledger span counts and the exact scoping on every run**, because a silent drop in one ledger is how a scoping bug hides while the total still looks healthy. Fault-injected and confirmed to fail on a one-word change to a real quote, and on a fabricated holding inside the New Mexico judgment section. On its first run against the EU ledger it caught a live defect: a Commission finding quoted as "Can be easily dismissed" when the release reads "can be easily dismissed" mid-sentence, which is the same class as a fabricated quote and invisible by eye. It proves **verbatim, never attribution**, which stays a by-eye check. **Since 2026-08-20 it also refuses ASR outright**: any declared source whose filename ends `-asr.txt` is a hard failure, with controls in both directions in the self-test. The corpus acquired its first machine transcription that day (the attorneys general press conference, whose Q&A exists in no other reachable form) and the danger is specific: verifying a quotation against a machine transcription proves that two machines agree, goes green while doing it, and every other checker here would agree with it. Such a file is a **pointer to a place in a recording**, never a text to quote; cite it with a timestamp and paraphrase, the same treatment the Dutch judgments get for the same underlying reason.

The `$` is now required, and the self-test carries a **third control** asserting that a bare integer does NOT satisfy a money figure, so the degradation cannot come back silently. **A second matcher bug, found 2026-08-28 by the first surface that ever carried a full amount:** `figures()` strips thousands separators from the surface figure, and `corpusHasFigure()` did not strip them from the corpus, so `$16,680,647,753.21` on a card could never match a ledger asserting exactly that number. Invisible for months because every figure the guard had checked was a short form (`$6M`, `$567M`, `~$1.4T`) whose numeric core carries no commas. ## Where an open thread goes (four homes, and the boundary is the point)

Added 2026-08-18, when `docs/issues/` was created as a general convention. **A fourth tracking
location is a real risk in a repository whose most persistent failure is a fact living somewhere
nobody re-reads**, so the boundary is narrow and it is checked before adding anything:

- **A question about the evidentiary record of one proceeding** goes in that ledger's **Tensions** section. There are more than sixty and they work: they are published with the ledger and read on every re-seed of that case. "Is the trial bifurcated" is a big question and it lives there.
- **Work being done now, with a shape and an order**, goes in a dated plan in `docs/plans/`. Plans close, and their follow-up lists are the outcome of an exercise rather than a standing queue.
- **A quoted span that cannot verify against its cache** goes in `KNOWN_DEVIATIONS` in `scripts/check-quotes.mjs`, which prints it on every run.
- **Everything else genuinely open** goes in `docs/issues/`, one dated file per thread, indexed, guarded by `npm run check:issues`. **That guard matched index rows to files and did not read the status column until 2026-08-20**, so it printed OK while the index described a closed thread as open. Presence in both directions was never the interesting half: an index whose rows all exist can still describe every one of them wrongly. The `Status` cell is now asserted against each file's own frontmatter, and a row without a readable status cell is itself a failure, so the table format is load-bearing. **A closed issue must also carry `revisited:`, accounting for every path in its `related:` list with a disposition (`updated` or `no-change-needed`) and a reason.** This is the repo's only guard on **prose staleness in `docs/research/` and `docs/plans/`**, and its shape is deliberate. Closing a thread falsifies sentences in the documents that depended on it, and no checker here can see that: they all read machine-readable surfaces. **A scan of research prose for words like "still" or "not obtained" is the wrong instrument and is explicitly ruled out**, for the reason the `check:surfaces` vocabulary is scoped hard to share cards: prose is allowed to discuss pending things, a research corpus is largely honest sentences about open questions, and one comment becoming a standing multi-file gate is a documented injury here. So the check asserts that **somebody looked**, at close time, in a place the answer is preserved. It cannot prove the disposition is true, and says so every run. Calibrated before it was written: of nine related-file pairs across five closed issues it would have fired on **two**, one of which was a real gap (the MDL ledger said nothing about *Doe 1*, the circuit's other Section 230 case, decided a week apart before the same district judge; now claim 43). **A rule that fires on two of nine is worth having; one firing on all nine would be noise.** The same guard also **recomputes the ledger-Tension count** that `docs/issues/README.md` declares, because that number was hand-written as 62 and was already wrong at the commit that wrote it (63 then, 64 on 2026-08-20). **That is the third count found living only in prose**, after the quote-span total and the guard list, and it got the same fix all three times: one declared home, recomputed by a tool. The counter aborts rather than comparing against zero if it finds no Tensions sections.

The test is **ownership, not importance**. Michigan's withdrawal is smaller than the bifurcation
question and belongs in issues, because no ledger claims it and the plan that found it has closed.

Three frontmatter fields are mandatory and each encodes a lesson this project paid for.
`closes_when` stops an issue being a mood. `trigger` is the press-conference finding: that item read
as dead research through two retries when the real state was one command away, so **a trigger beats
a reminder** and `none` is a real answer. `surface` is the plan's own insight that **verified is not
the same as publishable**, asked at open time rather than after the research.

**The checker cannot tell whether an issue duplicates a ledger Tension**, which is the failure this
directory most needs to avoid, and it says so on every run rather than letting green imply an answer
it does not have.
